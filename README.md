# 디스코드 거점 참여 봇

Google Cloud Ubuntu VM으로 이전할 때는 [Ubuntu 배포 안내](deploy/ubuntu.md)를 참고하세요.

모집 글에는 **참여 / 부속 우선 참여 / 참여 취소 / 참여 인원 현황 / 모집 마감** 버튼이 있습니다.
참여 버튼을 누르면 서버 닉네임의 `[길드명] 가문명`을 자동으로 읽습니다.
`[포도당] 디움`과 `[포도당]디움`을 모두 지원합니다. 동일 사용자가 다시 신청하면 현재 닉네임으로 수정됩니다.
`[P] 닉네임`은 길드 `Probe`로 조회하고 시트에 기록합니다. 현황에는 원래 서버 닉네임을 표시합니다.
관리자는 **모집 마감** 버튼으로 신청·취소를 막을 수 있습니다.

## 설치 (Windows PowerShell / Python 3.11 이상)

```powershell
cd C:\Users\chan\ponyangbot
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

`.env`가 이미 있다면 복사 명령을 다시 실행하지 마세요.

## 디스코드 설정

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 Application을 만들고 Bot 토큰을 발급합니다.
2. `.env`의 `DISCORD_TOKEN`에 토큰을 입력합니다. 토큰을 채팅이나 저장소에 올리지 마세요.
3. 디스코드 개발자 모드를 켜고 대상 서버의 ID를 복사해 `DISCORD_GUILD_ID`에 입력합니다.
4. OAuth2 URL Generator에서 `bot`, `applications.commands` 범위를 선택합니다.
5. 봇 권한으로 View Channels, Send Messages, Embed Links, Attach Files를 선택하여 서버에 초대합니다. 게시할 채널에서도 이 권한이 허용되어야 합니다.

입장 환영 기능을 위해 **Developer Portal → Bot → Privileged Gateway Intents → Server Members Intent**를 켜야 합니다.
Message Content Intent는 필요하지 않습니다. Server Members Intent를 끈 채 실행하면 연결이 거부될 수 있습니다.
명령은 설정한 서버에 등록됩니다. 모집 생성·마감·시트 상태 확인은 **서버 관리** 권한이 있는 사람만 사용할 수 있습니다.

### 새 멤버 환영과 이모지 역할

봇을 두 서버 모두에 초대하세요. 자동 환영은 새로 입장하는 일반 사용자에게만 전송됩니다.

| 서버 | 환영 채널 ID | 이모지 역할 |
| --- | --- | --- |
| 1128000592112009257 (포도당) | 1128245693652414495 | 🍇 길드원 / 💙 용병 |
| DISCORD_GUILD_ID (연맹) | 1209393580414603306 | ❤️ 포도당 / 💛 Probe / 💜 고라파덕 / 💙 용병 |

연맹의 💜는 이름이 정확히 `고라파덕`인 역할을 찾아 지급합니다. 해당 역할이 한 개 있어야 하며 봇 역할보다 아래에 있어야 합니다.
포도당 서버에는 이름이 정확히 `길드원`, `용병`인 역할이 각각 하나씩 있어야 합니다.
연맹 역할은 확인한 ID로 연결되어 있습니다. 역할을 삭제하고 새로 만든 경우 `welcome.py`의 ID도 변경해야 합니다.
봇에 **역할 관리**, 환영 채널의 **채널 보기·메시지 보내기·반응 추가·메시지 기록 보기** 권한을 허용하세요.
서버 설정의 역할 목록에서 **봇 역할을 지급할 역할들보다 위로** 올려야 합니다.
개인별 환영 메시지의 이모지는 해당 신규 멤버만 사용할 수 있으며, 다른 사람의 환영 글에 반응해도 역할을 지급하지 않습니다.
지급은 반응 추가 시 실행합니다. 반응을 취소해도 이미 지급된 역할은 회수하지 않습니다.
환영 메시지·사용자·역할 연결 정보는 기존 JSON에 저장되어 봇 재시작 후에도 사용할 수 있습니다.
21시 10분 정리 대상은 거점 모집 글뿐이므로 환영 메시지는 삭제하지 않습니다.

## 구글 스프레드시트 연결

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고 Google Sheets API를 활성화합니다.
2. IAM 및 관리자 → 서비스 계정에서 서비스 계정을 만들고 JSON 키를 발급합니다.
3. JSON 파일을 프로젝트 폴더의 `credentials.json`으로 저장합니다. `.gitignore`에서 제외됩니다.
4. 사용할 스프레드시트를 만들고 서비스 계정의 `client_email` 주소를 **편집자**로 공유합니다.
5. 시트 주소 `https://docs.google.com/spreadsheets/d/여기가ID/edit`에서 ID를 복사해 `.env`의 `GOOGLE_SPREADSHEET_ID`에 입력합니다.
6. `GOOGLE_APPLICATION_CREDENTIALS=credentials.json`으로 설정합니다.

모집·참여·대기·자동 게시 기록은 로컬 `data/bot.json`으로 관리합니다.
구글에는 `거점시트` 명단만 쓰고, `전체 직업 시트`에서 부속 역할을 읽습니다.
기존 `봇_거점`, `봇_참여` 탭은 첫 동기화에서 `data/backups/legacy-sheets-*.json`으로 백업한 다음 삭제합니다.
백업 저장에 실패하면 탭을 삭제하지 않습니다. 다른 탭은 삭제하거나 새로 만들지 않습니다.

### 거점시트 참여 명단

- 기존 `거점시트` 탭의 **K16:K115는 길드/예비, L16:L115는 가문명**으로 사용합니다.
- 정식 인원과 예비를 합해 최대 100명까지 저장합니다. K·L 값과 제목 F2만 RAW로 갱신하며 병합·드롭다운·서식과 다른 열의 수식은 보존합니다.
- 제목은 모집의 진행일 기준으로 `2026-10-28 수요일 25인 거점전 참여명단`처럼 자동 갱신합니다. 실제 동기화 날짜를 사용하지 않습니다.
- 해당 범위는 봇이 관리하므로 직접 입력한 이름은 다음 동기화 때 덮어써집니다.
- 새 모집을 만들면 다음 5분 동기화 때 이전 K·L 명단을 비우고 새 모집 명단으로 교체합니다.
- 최신 생성 모집 하나만 거점시트에 표시합니다. 이전 모집 버튼의 신청·취소는 차단하며 과거 기록은 JSON에 남습니다.
- K·L 명단은 부속 우선 참여자, 일반 참여자, 예비 순으로 다시 정렬합니다. 각 그룹 안에서는 신청 순서대로 표시합니다.
- 정원이 넘어도 일반 신청을 예비로 접수합니다. 25인 모집의 26번부터, 30인 모집의 31번부터 K열에 `예비`, L열에 가문명을 표시합니다. 원래 길드는 JSON에 보관합니다.
- 중간 참여자가 취소하면 뒤 인원을 당겨 빈칸 없이 씁니다. 첫 예비가 승격하면 K열은 원래 길드명으로 복구됩니다. 새 모집 시 이전 예비 명단도 비웁니다.
- 취소·우선 신청·대기 승격 시 명단 행이 이동합니다. 다른 열의 수식과 수동 입력 값은 옮기지 않으므로 수동 역할·특이사항·체크박스는 운영자가 확인해야 합니다.
- 새 모집 및 취소 시에도 직업·역할·특이사항·체크박스 열은 지우지 않습니다. 수동 입력한 정보는 운영자가 확인해야 합니다.
- 서버 닉네임 형식이 맞지 않거나 같은 가문명이 이미 신청된 경우 오류를 안내하고 등록하지 않습니다.
- 닉네임을 바꿨다면 참여 버튼을 다시 눌러 반영하세요. 과거 입력창으로 등록한 길드 미지정 사용자도 다시 신청하면 길드가 채워집니다.

### 부속 우선 참여

버튼을 누르면 현재 서버 닉네임으로 `전체 직업 시트`의 길드·가문명을 정확히 조회합니다.
공백이 있는 `역 할` 헤더와 가로로 나란히 놓인 길드별 표를 모두 지원합니다.

| 역할 | 우선 참여 TO |
| --- | --- |
| 화염탑 | 2명 |
| 신기전 | 1명 |
| 코끼리 | 1명 |
| 불퇴 | 1명 |
| 대포 | 2명 |

- 대상 역할이며 TO가 남으면 일반 참여자보다 먼저 배정합니다. 일반 참여자는 우선 버튼으로 전환할 수 있습니다.
- 25/30명 정원이 차 있으면 마지막 일반 참여자를 대기로 전환합니다. 대기는 `참여 인원 현황`에서 별도 표시합니다.
- 확정 참여자가 취소하면 대기 중인 일반 참여자가 신청 순서대로 승격합니다. 대기 중에도 참여 취소가 가능합니다.
- 역할 TO가 차면 우선 접수하지 않고 일반 참여 버튼을 안내합니다. 일반 신청은 전체 정원이 차도 예비로 접수합니다.
- 모든 자리가 우선 참여자로 찬 소규모 테스트에서는 전체 정원을 초과해 받지 않습니다.
- 본대 등 대상이 아닌 역할, 중복된 길드·가문명, 조회 실패는 우선 접수하지 않습니다.
- 같은 사용자의 중복 클릭은 TO를 중복 사용하지 않습니다. 우선 참여자의 닉네임 변경은 우선 버튼으로 재조회하세요.
- 역할은 우선 버튼을 누를 때 검증합니다. 이후 직업 시트를 수정해도 이미 배정된 역할은 자동 변경되지 않습니다.

## 실행과 사용

### 자동 모집 일정

한국시간 매일 21시 30분에 다음 날 21시 시작하는 **1단거점** 모집을 게시합니다.

매일 21시 10분에는 지난 거점 모집을 자동 마감·보관하고 해당 모집 메시지를 삭제합니다.
현재 시트가 그 모집을 표시 중이면 K16:L115 명단과 F2 제목을 비웁니다. 다른 열의 수식·서식·체크박스는 변경하지 않습니다.
JSON의 과거 신청 기록은 남습니다. 봇이 꺼져 있었다면 재시작 시 지난 정리를 처리하며, 미래 날짜 모집은 지우지 않습니다.
메시지는 기록된 채널·메시지 ID와 봇 작성자 여부를 확인해 삭제합니다. 이번 버전부터 수동/테스트 모집도 ID를 저장합니다.
이전 버전에서 ID를 저장하지 않은 수동 모집 글은 직접 삭제해야 합니다.
정리는 30초 간격으로 확인하며, 시트 보호나 디스코드 권한 문제로 실패하면 재시도합니다.

| 진행 요일 | 정원 |
| --- | --- |
| 수·금 | 25명 |
| 화·목·일 | 30명 |
| 월·토 | 일정 없음 |

월요일 거점은 일단 중단합니다. 일요일·금요일 21시 30분에는 게시하지 않습니다.
월요일 21시 30분에는 화요일 모집을, 토요일 21시 30분에는 일요일 모집을 게시합니다.
`.env`의 `AUTO_RECRUIT_CHANNEL_ID=1292922030043168940`, `EVENT_START_TIME=21:00`으로 설정합니다.
자동 모집을 끄려면 `AUTO_RECRUIT_CHANNEL_ID` 값을 비우세요.
봇에 해당 채널의 **메시지 기록 보기(Read Message History)** 권한도 필요합니다.
모집 글은 날짜·요일·정원을 넣은 거점전 안내 양식으로 게시하며 `@everyone`을 호출합니다.
실제 알림을 보내려면 봇에 **@everyone, @here 및 모든 역할 멘션** 권한을 허용하세요.
모집 마감 수정 시에는 재호출하지 않습니다. 새 양식은 이후 게시물부터 적용합니다.
본문의 참여인원은 모집 정원이며, 실제 신청자는 **참여 인원 현황** 버튼에서 확인합니다.
직업·역할 안내 문구의 `각 길드별 직업시트`는 사용자가 관리하는 별도 시트를 뜻합니다.
봇은 각 길드별 시트를 생성하지 않습니다. 부속 역할은 `전체 직업 시트`에 반영된 값을 조회합니다.
30초 간격으로 게시 시각을 확인하므로 정상 연결 상태에서 21시 30분부터 약 30초 이내에 게시합니다.
봇이 꺼져 있었다면 재실행 시 당일 시작 전까지 누락된 모집을 게시합니다. 최초 실행에도 같은 규칙을 적용합니다.
게시 여부를 JSON에 보관하고, 전송 후 저장에 실패한 경우 채널 기록을 조회해 중복을 방지합니다.
이미 게시한 글을 삭제하더라도 자동 재게시하지 않습니다. 수동 `/거점생성`은 별도 모집입니다.

```powershell
.\.venv\Scripts\python bot.py
```

디스코드에서 다음 명령을 사용합니다.

```text
/거점생성 거점명:칼페온 진행일시:2026-10-30 21:00 정원:30
/시트상태
```

### 테스트 명령

`/거점테스트` 또는 `/거점테스트 정원:2`를 실행하면 현재 채널에 실제 모집과 동일한 글을 즉시 게시합니다.
서버 관리 권한이 필요하며 기본 정원은 25명, 진행일은 내일 21시입니다.
`@everyone`을 호출하고 실제 JSON 및 거점시트에 기록합니다. 다음 5분 동기화 때 이전 명단을 교체합니다.
부속 우선 참여를 포함한 모든 버튼은 운영 모집과 동일합니다. 15분 만료가 없으며 재시작 후에도 유지됩니다.
자동 게시 일정은 계속 작동하며, 이후 새 모집이 생성되면 그 모집이 최신 명단이 됩니다.

진행일시는 미래의 한국시간을 입력하세요. 정원 생략 시 요일별 25/30명이며 직접 지정 시 1~30명입니다.
마감은 관리자가 버튼으로 진행합니다. 시작 시각에 자동 마감하지 않습니다.
공지의 참여 인원은 고정 표시하지 않으며 **참여 인원 현황** 버튼으로 최신 명단·인원·마감 상태를 확인합니다.

## 저장과 운영

- `data/bot.json`에 모집과 참여 상태를 먼저 저장하고, 변경이 있으면 약 5분 간격으로 시트에 반영합니다. 구글 요청 소요 시간만큼 더 걸릴 수 있습니다.
- 기존 `.env`의 `DATABASE_PATH=data/bot.db`도 지원합니다. 같은 경로의 `.json`을 사용하며 JSON이 없으면 기존 DB에서 한 번 이관합니다. 원본 DB는 삭제하지 않습니다.
- JSON 저장은 임시 파일에 완전히 쓴 뒤 교체합니다. 저장 실패 시 신청 성공으로 처리하지 않습니다. 손상된 JSON을 발견하면 빈 파일로 덮어쓰지 않고 실행을 중단합니다.
- 구글 연결 장애 시 신청은 로컬에 보관되며 자동 재시도합니다. `/시트상태`로 확인하세요.
- 재시작 후에도 기존 메시지의 버튼을 사용할 수 있습니다. `data` 폴더를 삭제하지 마세요.
- 취소한 기록은 JSON에 `취소`로 남고 거점시트에서는 제외됩니다. 각 모집·사용자당 최신 상태이며 전체 변경 이력은 아닙니다.
- 디스코드 ID는 문자열, 사용자 입력은 RAW 값으로 저장하여 숫자 반올림과 수식 실행을 방지합니다.
- 봇은 **하나의 프로세스만** 실행하세요. 계속 동작하려면 PC 또는 서버가 켜져 있어야 합니다.
- JSON은 원본입니다. 실행 중인 봇을 먼저 종료한 뒤 재시작하세요. 서버 이전 시 `data` 폴더 전체와 설정을 옮기세요. 실행 중 JSON을 직접 수정하지 마세요.
- 현재 방식은 변경 시 전체 명단을 동기화하므로 소규모 길드 운영용입니다.

## 요일별 관리자 패널

서버 관리 권한으로 `/관리자패널`을 실행합니다. 본인에게만 표시되는 패널에서 요일을 선택한 후 미진행·1단·2단을 선택하면 즉시 JSON에 저장됩니다. 다시 변경할 때까지 매주 반복되며 재시작해도 유지됩니다. 패널은 10분 후 만료되지만 명령어로 다시 열 수 있습니다.

기존 기본값은 월·토 미진행, 나머지 요일 1단입니다. 월요일도 패널에서 활성화할 수 있고 토요일은 미진행 또는 100인 공성전을 설정할 수 있습니다.

| 요일 | 1단 | 2단 |
|---|---|---|
| 월·수 | 25명 | 40명 |
| 화·목 | 30명 | 40명 |
| 금 | 25명 | 50명 |
| 일 | 30명 | 50명 |

1단 공지는 발레노스·세렌디아, 2단 공지는 칼페온·올루키타 및 2단 제한 문구를 표시합니다. 설정 변경은 새로 게시하는 모집부터 적용되며 이미 게시된 모집의 단계·정원·명단은 유지됩니다. 21:10 정리, 21:30 다음 날 모집 게시, 21:00 거점 시작은 동일합니다. 수동 `/거점생성`에서는 거점명에 `2단`을 포함하면 2단 공지를 사용하며 정원을 최대 50명까지 지정할 수 있습니다.


관리자 패널 최상단에는 다음 일정의 날짜·요일·종류·정원·시작 시각이 표시됩니다. 이미 게시된 모집은 저장된 모집 정보를 우선 표시합니다. 아래에는 월~일 전체 설정을 표시합니다. 토요일은 제한 발레노스 촌성, 제한 발렌시아 성, 무제한 메디아 성 중 선택하며 모두 100인입니다. 설정은 JSON에 지속 저장됩니다. 공성전은 20:00에 시작합니다. 거점전은 EVENT_START_TIME(기본 21:00)을 사용합니다.

2단·공성전 준비물: 녹아내린 구리조각 100개 + 철 주괴 100개,지뢰류, 비약, 석재, 부속건설도구, (강화)화염탑용기름, (대)신기전화살, 정제수


## 부속 신청 시간 및 용병 추가

거점전 부속 우선 참여는 시작 1시간 전(기본 20:00)부터 신청할 수 없습니다. 공지에 안내하며 차단 시 일반 참여를 안내합니다. 시트 조회 중 마감 시각이 지나도 우선 등록되지 않습니다. 기존 우선 신청자는 유지하고 공성전은 이 제한에서 제외합니다.

모집 마감 버튼은 용병 추가로 교체했습니다. 서버 관리 권한을 가진 관리자가 가문명을 입력하면 `[용병] 가문명`으로 일반 신청 순서에 추가됩니다. 정원 초과 시 예비 처리하며 같은 가문명 중복 등록을 막습니다. JSON에 저장하고 기존 시트 동기화에 반영합니다. 수동 용병은 디스코드 계정과 연결되지 않습니다.

재시작 시 저장된 모집 메시지의 버튼·안내문을 갱신하며 @everyone 알림을 다시 보내지 않습니다. 공성전 자동 모집과 관리자 패널의 공성 시작 시각은 20:00입니다.


고라파덕 길드는 `[고라파덕] 가문명` 또는 `[고라파덕]가문명` 형식으로 참여합니다. 거점시트 K열에 고라파덕, L열에 가문명을 기록하며 전체 직업 시트의 고라파덕·가문명으로 부속 역할을 조회합니다. 시트의 길드 드롭다운에도 고라파덕을 추가하고 전체 직업 시트에 해당 길드원 정보를 등록해야 합니다. 새 환영 메시지에서는 💜 고라파덕 역할을 선택할 수 있습니다. 기존에 전송된 환영 메시지는 자동 수정하지 않습니다.
